# AGENTS.md — dianweitest (5-Axis Robotic Arm)

## Build & Flash

```bash
# Configure (must use presets — Ninja + GCC ARM toolchain)
cmake --preset Debug

# Build
cmake --build build/Debug

# Flash (not automated in CMake; use ST-Link / OpenOCD)
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program build/Debug/dianweitest.elf verify reset exit"
```

- **Build output**: `build/Debug/dianweitest.elf`, `.hex`, `.map`
- **IntelliSense**: `.clangd` points to `build/Debug/compile_commands.json` (generated by CMake)

## Architecture Overview

```
[4x Potentiometers] ──(analog)──> PA0-PA3 ──> ADC1 ──DMA1_CH1──> adc_values[4]
                                                                       │
                                                               map_range() + pulse_to_angle()
                                                                       │
                         ┌─────────────────┬───────────┬───────────────┤
                         │                 │           │               │
              SERVO_BASE(p) ──TIM1_CH1──> PA8    TIM1_CH2──> PA9   TIM1_CH3──> PA10
                         │                 │           │               │
              TIM1_CH4──> PA11          TIM3_CH1──> PA6
                         │
              [Gripper button] PA4 ──> digitalRead ──> HAND open/close

[OLED 128x64] ──software I2C (PB8=SCL, PB9=SDA)──> SSD1306
```

## CubeMX Code Generation Rules (CRITICAL)

**STM32CubeMX regenerates code between `USER CODE BEGIN` / `USER CODE END` markers only.**
All custom code MUST stay inside these guarded regions. Outside markers = will be overwritten.

- `main.c`: Custom init in `USER CODE BEGIN 2`, loop in `USER CODE BEGIN WHILE` / `USER CODE BEGIN 3`, helper functions in `USER CODE BEGIN 4`
- `main.h`: Servo macros and global externs in `USER CODE BEGIN EM` / `USER CODE BEGIN EFP`
- `stm32f1xx_it.c`, `stm32f1xx_hal_msp.c`: ISRs and MSP init in their respective USER CODE regions

## Servo Control

- **5 servos** via hardware PWM, 50Hz, 1μs resolution (PSC=71, ARR=19999)
- **Pulse update**: Direct CCR register writes via `__HAL_TIM_SET_COMPARE()` macros — bypasses HAL overhead
- **Pulse range**: 650μs (0°) ~ 2350μs (180°), mid = 1500μs (90°)
- **Gripper**: HAND_OPEN = 439μs, HAND_CLOSE = 879μs
- **Mapping is reversed**: ADC high (3500) → pulse low (650) → angle 0; ADC low (600) → pulse high (2350) → angle 180

| Servo | Timer | Channel | Pin | Macro |
|---|---|---|---|---|
| Base | TIM1 | CH1 | PA8 | `SERVO_BASE(p)` |
| Shoulder | TIM1 | CH2 | PA9 | `SERVO_SHOULDER(p)` |
| Elbow | TIM1 | CH3 | PA10 | `SERVO_ELBOW(p)` |
| Wrist | TIM1 | CH4 | PA11 | `SERVO_WRIST(p)` |
| Hand/Gripper | TIM3 | CH1 | PA6 | `SERVO_HAND(p)` |

## Peripheral Gotchas

1. **TIM3 clock = 72MHz, not 36MHz**: STM32F1 "APB1 ×2" rule — when APB1 prescaler ≠ 1, timer clocks double. PCLK1=36MHz → TIM3 clk=72MHz.
2. **ADC calibration is mandatory**: `HAL_ADCEx_Calibration_Start()` must run after `HAL_ADC_Init()` and before `HAL_ADC_Start_DMA()`.
3. **ADC DMA buffer is `volatile uint16_t[4]`**: Halfword aligned, not `uint32_t`. The `.ioc` and MSP init use `DMA_PDATAALIGN_HALFWORD`.
4. **No hardware I2C**: All I2C is bit-banged via `soft_i2c.c` using DWT cycle counter for microsecond delays. PB9 direction is switched at register level (`GPIOB->CRH`) for ACK reading.
5. **OLED avoids `%f`**: Uses fixed-point integer math (`raw*3300/4096`) because newlib-nano's `%f` requires heap and has compatibility issues.
6. **Main loop rate = 10Hz**: `HAL_Delay(100)` in loop; ADC DMA runs independently in background.
7. **No interrupt on PWM timers**: Pure hardware PWM, no TIM1/TIM3 interrupts enabled.

## Hardware Notes

- **Servos need external 5-6V power** with common ground to STM32. Do NOT power servos from the STM32's 3.3V regulator.
- **OLED I2C address**: 0x3C (write = 0x78)
- **Clock source**: 8MHz HSE crystal on PD0/PD1 → PLL ×9 → 72MHz SYSCLK

## What This Project Does NOT Have

- No PID controllers or feedback loops (open-loop control)
- No inverse/forward kinematics
- No UART/serial output (the OLED replaces serial debugging)
- No RTOS (bare metal, single `while(1)` loop)
- No encoder feedback on servos
- No external libraries beyond STM32 HAL
